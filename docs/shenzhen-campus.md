# 深圳校区宿舍：从电脑验证到原厂路由器接入

这份路线来自深圳校区一个本人宿舍墙口和一台已核实的 AX3000T **RD03v2**。本次保留原厂 **2.0.28**，由标准 MiniEAP 完成校园侧认证，没有刷 OpenWrt。它说明如何分阶段建立证据，不保证其他房间、硬件版本或未来接入策略相同。匿名结果见[现场记录](field-results.md)，参考项目与独立实现边界见[来源说明](../REFERENCES.md)。

学校的[个人用户有线接入页面](https://inc.sysu.edu.cn/service/wired-network-access)提供学生操作流程和 Windows 锐捷 v4.97 下载，要求自动获取地址并用本人的 NetID 认证。[2023 年搬迁指引](https://inc.sysu.edu.cn/article/1459)将深圳学生宿舍有线接入与南校园的锐捷方式归在一起；这是历史背景，不能代替当前墙口的协议实测。

## 1. 先用 Windows 和官方客户端证明墙口可用

记录 Windows 版本和架构、实际物理有线网卡、链路、地址与 DNS 获取方式、路由、客户端版本和相关服务状态。保存原有设置，区分有线、无线和虚拟接口。千兆协商只证明链路速率；链路本地自分配地址且没有网关时，尚不能当作已接入校园网。

从学校页面进入官方下载，核验来源和安装器，再正常安装。仅将目标有线接口的 IPv4、DNS 改为自动获取，确认 DHCP 服务可用。使用锐捷时，让它接管该接口的认证，避免 Windows 原生有线 802.1X 与之争用。学校的[锐捷 FAQ](https://inc.sysu.edu.cn/cat/152)明确提到此冲突，也说明认证成功后仍需成功获取 DHCP 地址。本项目不把关闭安全防护、全局网络重置或卸载驱动作为常规第一步。

在锐捷中选择真正接墙线的物理网卡。本人只在本机官方窗口输入 NetID 和密码，发起一次认证；不要把密码写进聊天、命令行或日志。失败时保留脱敏错误并先查原因，不连续自动重试。客户端启动或兼容性失败，也不能直接证明墙口未开放。

看到成功提示后，再核对目标接口的有效地址、默认网关和 DNS。若仍没有地址，重点检查 DHCP，只针对这一接口处理。网页能打开还不够：需要证明访问使用该有线源接口及其路由，并保持正常 TLS 验证、排除代理代发。短暂关闭 Wi-Fi 是一种验证方式，但必须能恢复；若远程控制依赖它，应先安排本机配合，或使用可靠的来源绑定验证。

这一阶段成功之前，不把路由器配置或固件变更混进墙口诊断。已取得的直连结果可以沿用，不必为每次后续故障重做整套测试。

## 2. 协议判断只依据当前头部证据

电脑曾保存 PEAP/EAP-MSCHAPv2 配置，这只能说明本机历史设置。本次当前墙口的接收方向出现 Identity、MD5 请求和 EAP Success，标准 MiniEAP 也取得实际成功，因此本项目有 **EAP-MD5 可用**的现场证据。它不证明学校所有墙口永远只使用这一方法，也不证明已经核验服务端身份或全部私有扩展。

公开工具只用于本人已选定接口的被动协议头诊断，不取代官方客户端：

```text
python tools/eap_metadata.py --help
python tools/eap_metadata.py --list
```

如需 Windows 采集，先依[使用说明](usage.md)另从 Npcap 官网准备并核验依赖，再手动确认真实物理有线接口。Npcap 显示 Ethernet 链路类型本身不能证明接口是物理有线。只进行一次受控重连，输出严格的数字/枚举头部，不保存完整 PCAP、账号、挑战值或客户端日志正文。

Linux 观察器只保留 23 字节前缀；原 ARM/Linux 组合已证明接收方向可见，发送方向未获保证，不能从 TX 为零推断客户端没有应答。Windows 整理版前端仍只有离线解析与边界测试，尚未重新做现场采集验收。连续观察段及分段日志也不能任意拼成一个虚构握手。

## 3. 本次路由器的接线与部署前提

本机固定端口后，从路由器背面面向整排网口观察，最左口用于校园 WAN，最右口用于电脑 LAN；本机校园 WAN 接口为 `eth0.1`。这是已核实并固定后的本机布局，不是所有 AX3000T 的通用端口定义；其他设备的物理口和LAN/VLAN映射需分别核验。

```text
日常上网：校园墙口 ── 固定 WAN 口 → RD03v2 → 私人 Wi-Fi / LAN → 个人设备
准备管理：电脑有线口 ── LAN 口 → RD03v2，校园 WAN 暂不接
```

部署前至少需要：

- 重新确认实际型号、固件、CPU/ABI、物理口和 VLAN 映射；不能把同名 RD03、RD23 的文件当作 RD03v2 文件。
- 本人已有受控、可恢复且仅限私人 LAN 的管理入口，并核验管理身份。没有此入口时，本仓库不能直接完成部署。
- 私人主 AP 和管理员已安全设置；WAN 不进私人 LAN 桥，私人 DHCP 不服务校园侧，实际防火墙路径已核验。
- 本人的离机备份、文件摘要、原始配置记录和具体回滚办法。备份留本地，不发布到仓库；未演练的恢复方法不能算已具备恢复能力。
- 已为目标 ABI 构建并验证的 MiniEAP、观察器、正常 Logoff 工具及设备专属安全门。凭据只在本机安全输入，在设备受限目录保存，目录 `0700`、配置 `0600`。

公开的[源码准备与构建](usage.md)和[离线服务生成器](../stock-service/README.md)能够帮助审查实现，但**不是安装器**。尤其没有随包提供可直接用于他人设备的 `gate.lua`、正常 Logoff 二进制、管理密钥或认证配置。生成 shell 文本和编译通过，不等于可以上传执行。

本次原厂路线没有使用启动 U 盘，也没有刷写固件、原始分区或修改启动环境；服务文件保存在原厂数据目录。本页不包含通用 root 获取、漏洞利用、恢复出厂或刷机教程；这些不能作为“先试一下”的前置动作。

## 4. 只有一根网线时如何安排

一根线无法同时维持“电脑直连校园墙口”和“墙口接路由器 WAN”。应按阶段换接，不能用同时具备两根线的假设编排步骤。

1. 先把线用于墙口到电脑，完成前述官方客户端验证；保留可恢复的备用管理网络。
2. 将同一根线改为电脑到路由器 LAN，WAN 留空。在此阶段核对端口、管理身份、安全配置与私人 AP；没有校园上游是预期状态。
3. 在换墙线之前，先证明电脑能通过本人私人 Wi-Fi 获得私人 DHCP、路由到正确的管理入口，并可恢复原连接。此处通过只证明管理通路，不证明校园网已通。
4. 准备好独立恢复守卫或本机回退办法后，再把同一根线改为墙口到固定 WAN；电脑改用私人 Wi-Fi 管理。不要让电脑锐捷与路由器 MiniEAP 同时争用同一上游会话。
5. 完成路由器认证、DHCP 和真实来源验证。若远程切网不能可靠恢复，就停在已知可管理的状态，待现场配合；不要假定远控会自动重连。

单线方式也限制测速对照：没有额外连接条件时，直连与路由路径只能分时测，不能宣称做了严格同时段 A/B 比较。

## 5. 服务维护与验收顺序

校园侧只保持一个认证客户端。成功后保持该进程，观察器换段不应重启认证。正常停止和普通关机要有受控 Logoff 与顺序管理；进程被杀不等于已正常注销。真实 EAP Failure 或未知凭据尝试应锁存，不能为“恢复”自动抹掉。

本机 v2 对已成功会话的链路恢复采用有界预算：同一次开机内，每 1800 秒最多预留两次恢复工作流，距上次实际凭据进程启动至少 300 秒。超预算等待不等于认证失败。这是实现策略；物理拔插恢复仍待验，不能把代码路径当作验收结果。

| 验收层 | 必须取得的证据 |
| --- | --- |
| 认证 | 当前接口、当前唯一客户端、真实 Success 或明确 Failure；不是旧配置推测 |
| DHCP/DNS | 正确 WAN 的有效租约、网关和 DNS；Success 本身不能代替 |
| 实际外网路径 | 私人接口源地址、实际下一跳、正常 TLS 的固定网站访问，排除备用 Wi-Fi 与代理 |
| 普通重启 | 新启动身份、正确文件与安全门、客户端归属、重新认证和来源绑定访问 |
| 冷启动、物理断线、续租 | 分别实测，不能用普通重启成功代替 |
| 多设备与广播 | 多台同时活跃，以及两端真实 mDNS/SSDP/广播收发；桥配置和关联数不够 |
| 长时间可用 | 明确起止、采样间隔、未观察空窗和异常退出；未满 24 小时不记通过 |

## 6. 故障分层

| 现象 | 先查什么 |
| --- | --- |
| 官方客户端装不上或打不开 | 安装器来源、系统架构、精确兼容错误；尚不能判断墙口 |
| 找服务器或网卡未连接 | 真实物理接口、网线和端口、客户端选择、原生 802.1X 是否争用 |
| 当前 MD5 之后明确 Failure | 停止主动重试，保留头部顺序与 ID，区分账号、会话和服务器拒绝 |
| Success 但没有地址 | 目标接口 DHCP、租约和网关，不做全局重置 |
| 有地址但访问失败 | 分开查 DNS、路由、TLS、测试目标及是否借用了备用网络 |
| AP 不可见或电脑连不上 | 分开查扫描、关联、无线状态和私人 DHCP，不先归因校园认证 |
| 采集器称离线但进程与网站正常 | 独立查 PID/父进程、原始严格状态和成功回执；本项目曾修正 null、回执和 PID 复用误判 |
| 下载返回错误或超时 | 核对每条传输的状态码、实际字节和完成状态；程序退出正常也可能包含失败项 |

更多实现问题见[故障排查](troubleshooting.md)。向学校求助可从官方[锐捷 FAQ](https://inc.sysu.edu.cn/cat/152)进入服务渠道，提供脱敏时间、端口与错误类别，不发送密码、完整日志或私人备份。
