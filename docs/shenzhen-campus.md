# 深圳校区宿舍：让 AX3000T 直接登录校园网

电脑插墙口、打开锐捷就能上网，但手机和平板怎么办？这次的做法是让路由器负责登录校园网，再把网络分给自己的设备。配置完成后，电脑可以关机或带走，锐捷也不用一直开着。

用到的路由器是 **AX3000T RD03v2，原厂固件 2.0.28**。最终保留了原厂系统，在路由器上运行标准 MiniEAP，使用 EAP-MD5 认证，未启用 `rjv3`。没有刷 OpenWrt，也没有用到启动 U 盘。

下面按实际操作顺序讲这条路线。仓库已整理出采集工具、MiniEAP 构建脚本和服务源码；新设备的完整安装流程还没有整理完，缺少设备检查用的 `gate.lua`、正常注销用的 Logoff 工具及部署入口。因此，这是一份接入过程和实现参考，暂时还不能从头复制命令装到另一台路由器上。[源码准备与构建](usage.md)和[服务说明](../stock-service/README.md)介绍了现有工具。

## 第一步：先让电脑直连成功

先把网线从宿舍墙口接到电脑。这一步是为了回答两个问题：墙口能不能用，自己的账号能不能在这里登录。先得到这两个答案，后面路由器有问题时才好找原因。

Windows 中找到实际接线的物理网卡，把它的 IPv4 和 DNS 设为自动获取。最初这台电脑虽然显示 1Gbps，拿到的却是 `169.254` 开头的地址，也没有默认网关。这说明网线已建立连接，电脑还没拿到校园网分配的地址。

从学校的[有线接入页面](https://inc.sysu.edu.cn/service/wired-network-access)下载 Windows 锐捷客户端，选择这张有线网卡，用自己的 NetID 登录。使用锐捷时，关闭该网卡上 Windows 自带的有线 802.1X，让锐捷负责认证；学校的[锐捷 FAQ](https://inc.sysu.edu.cn/cat/152)也提到了两者可能冲突。

看到“认证成功”后，还要看这张网卡有没有拿到有效地址、网关和 DNS。Wi-Fi 同时连着时，网页能打开很容易造成误判：应核对访问走的网卡和路由，或在能够恢复连接的前提下暂时关闭 Wi-Fi。这次电脑直连已完成这些检查，可以继续处理路由器。

如果锐捷成功但地址仍是 `169.254`，先查有线接口的 DHCP；如果客户端装不上，先处理安装和兼容问题。这两种情况都还没到判断路由器方案的时候。

## 第二步：看墙口实际用了什么认证

电脑以前保存过 PEAP/EAP-MSCHAPv2 配置，但保存过什么，不代表墙口现在就用什么。学校的[深圳校区历史指引](https://inc.sysu.edu.cn/article/1459)说明宿舍采用锐捷接入，也没有替我们回答具体协议。

这次是在官方锐捷进行一次重连时，查看 EAPOL 协议头。接收方向看到了 Identity、MD5 请求和 EAP Success；随后路由器上的标准 MiniEAP 也认证成功，所以选择了 **EAP-MD5**。南校园项目使用的 `rjv3` 在这里没有启用。

Windows 采集工具的入口是：

```text
python tools/eap_metadata.py --list
python tools/eap_metadata.py --help
```

采集需要先从 Npcap 官网安装依赖，再选择真正接墙口的有线接口。具体参数见[使用说明](usage.md)。工具只输出协议头字段，不保存完整抓包；账号密码只在本机输入，不放进仓库。公开整理版 Windows 工具目前做过离线测试，尚未重新现场采集。

还有一个容易误读的地方：这次 Linux 观察器能看到接收方向，发送方向没有确认能完整看到。因此，日志里没出现发送记录时，不能单凭这一点说客户端没应答。

## 第三步：把认证放到原厂路由器上

这次拿到路由器管理权限、完成离机备份后，发现原厂系统可以运行所需程序，就保留了原厂固件。路由器上的分工是：

| 部件 | 做什么 |
| --- | --- |
| MiniEAP | 在校园 WAN 接口上完成认证 |
| 原厂 DHCP 客户端 | 向校园网获取地址、网关和 DNS |
| 原厂路由、NAT 和 Wi-Fi | 给自己的电脑、手机和平板提供网络 |
| 配套服务 | 开机启动认证、维护进程、处理正常注销和有限重连 |

本台校园 WAN 的接口名是 `eth0.1`。程序和配置存放在原厂数据目录，启动时由配套服务运行。校园网密码只在本机填写，实际配置保存在路由器受限目录，未放进公开源码。

迁移到另一台机器时，需要先弄清硬件版本、固件、程序架构和端口映射，再准备管理入口、备份与回退办法。尤其不要拿 RD03、RD23 或其他版本的文件直接套到 RD03v2。仓库中的服务生成器也依赖前面提到的外部组件，补齐这些组件之后才谈得上安装。

这里的网络结构很简单：校园 WAN 单独接上游，私人 2.4GHz、5GHz 和 LAN 放在同一个局域网；路由器向私人设备分配地址。校园侧只运行一个认证客户端，电脑锐捷完成直连测试后便退出。

## 第四步：只有一根网线，分阶段换接

一根网线够用。先拿它配置路由器，之后让它一直连接墙口和路由器；电脑改用 Wi-Fi。

**本台固定后的口位：面对路由器背面的整排网口，最左口为校园 WAN，最右口为电脑 LAN。** 这是这台设备调整后的布局，换机器时要重新确认。

1. **先配置：电脑 → 路由器 LAN。** 墙口暂时不接。设置私人 Wi-Fi 和管理密码，完成认证程序的准备。
2. **先试私人 Wi-Fi。** 电脑连到刚设置的 Wi-Fi，确认能打开路由器管理页。此时没有互联网是正常的，因为墙口还没接入。
3. **再换线：墙口 → 路由器 WAN。** 把电脑这一端拔下接墙口，路由器这一端移到固定 WAN 口。电脑继续通过私人 Wi-Fi 管理路由器。
4. **等路由器登录，再看地址和外网。** MiniEAP 认证成功后，确认 WAN 拿到 DHCP 地址、网关和 DNS，然后用私人 Wi-Fi 打开校内、外网站点。

最后接法是：

```text
宿舍墙口 ── 一根网线 ── 路由器 WAN
                              │
                       私人 Wi-Fi / LAN
                              │
                       电脑、手机、平板
```

如果操作依赖远程连接，换线前要先试通私人 Wi-Fi 管理路径，并留好恢复办法；这次切网时就出现过未按计划自动切回的情况。不要把“稍后会自动连回来”当作唯一退路。

## 配好之后，平时怎么用

墙线留在 WAN，个人设备连接自己的 Wi-Fi 即可。认证运行在路由器上，电脑是否开机、是否在宿舍，不影响它继续工作。以后需要排查时，通常也能通过私人 Wi-Fi 进入管理页；只有 Wi-Fi 或管理入口本身出了问题，才可能需要再用网线直连。

本次已测试过一次普通重启：路由器重新启动后能自动认证、获取地址并上网。断电再通电的冷启动还没做，不能直接拿普通重启结果代替。手机关闭移动数据后能上网，另外两台设备也分别使用成功；四台同时活跃的测试还没完成。

服务给重连留了节制：同一次开机内，任意连续 30 分钟内最多预留两次恢复流程，两次实际认证启动至少间隔 5 分钟。如果服务器明确拒绝认证，服务会停下来保留错误，等待处理，而不是不断尝试密码。物理拔插后的自动恢复还需要单独测试。

这次原计划观察 24 小时，实际记录了约 6 小时 35 分钟：两站成对 HTTPS 探测 396 次全部通过，服务检查 80 次全部在线，随后观察进程退出。目前还没有完整的 24 小时结果。测速、时间和后续待测项放在[现场记录](field-results.md)，日常优化建议见[网络体验](network-experience.md)。

## 突然上不了网，从哪里查

先分清是连不上自己的 Wi-Fi，还是连上了却没有互联网。前者先看无线和私人 DHCP；后者按下面顺序往上游查。

| 看到的情况 | 接下来做什么 |
| --- | --- |
| Wi-Fi 能连，但打不开路由器管理页 | 看设备有没有取得私人地址，确认连的是自己的网络 |
| WAN 显示未连接 | 看墙线、固定 WAN 口和链路状态 |
| MiniEAP 一直找服务器 | 核对校园接口和接线，确认没有另一份认证客户端同时运行 |
| 明确提示认证失败 | 先停重试，查看具体错误，检查账号、密码和旧会话 |
| 已认证，WAN 没地址或仍是 `169.254` | 查 WAN 的 DHCP，不重置整台电脑或路由器 |
| WAN 有地址，域名打不开 | 分别检查 DNS、默认路由和目标网站 |
| 只有某个测速下载失败 | 看 HTTP 状态、收到的字节和是否超时，换目标复查 |
| 观察程序显示离线，但设备还能正常上网 | 检查观察程序本身，再查认证进程；本次就发生过观察器退出 |

认证成功、DHCP 拿到地址、设备真正能访问外网，是相邻但不同的三步。按这个顺序查，通常比一遇到问题就重启、重登更快。更细的实现问题见[故障排查](troubleshooting.md)。
