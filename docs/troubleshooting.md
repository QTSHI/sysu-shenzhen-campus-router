# 故障排查

| 现象 | 优先证据与处理 |
|---|---|
| 客户端启动不了 | 核查 CPU/ABI、动态链接器、权限和精确错误；不能由安装失败推断墙口不可用 |
| 没有观察记录 | 先确认采集程序确实启动、选中正确接口并绑定成功；启动失败不等于零流量 |
| EAP Failure | 保留严格头部顺序和 ID，停止主动重试；先区分是否发生在本轮 Identity/MD5 后 |
| Success 后没有地址 | 检查目标 WAN 的 DHCP、网关和 DNS；不要全局续租或重置电脑网络 |
| 网站能打开但路径不明 | 检查源地址、接口及下一跳，再做源绑定 HTTPS；备用校园 Wi-Fi可能承担流量 |
| 私人 5GHz 连接失败 | 区分缓存扫描、无线可见性、关联与 DHCP；没有路由器诊断时不能判认证失败 |
| 重启后有旧故障锁 | 核对故障所属启动、当前凭据意图与进程；不自动清真实失败或未知尝试 |
| 采集器报服务不在线 | 独立核对真实 PID/父进程/摘要和源 HTTPS；采集器变量遮蔽曾导致假阴性 |

## 会话交接

停止成功客户端不等于已发送正常 EAPOL-Logoff。现场曾在交接后收到明确 Failure，单次正常注销加冷却后恢复；这支持会话因素参与，不能证明唯一根因。不要通过放宽 Failure 处理或无限重试解决。未知操作必须先只读查证。

## 无线可见性

原厂代码存在 CAC 状态查询及特定动态硬件模式切换时的等待分支；这不能证明每次 5GHz 暂不可见都是 DFS。应读取本机实际信道、带宽和状态，避免无证据改信道或关闭监管功能。先刷新本人目标网络的扫描，再按新窗口核验；不要读取或导出其他已保存无线密码。

## 长连接与 24 小时

单次 Success、进程存活和日志文件存在，都不证明持续公网在线。记录起止时间、真实 HTTPS 样本、租约与重新认证事件；采样中断、修复或换线应注明。未达到实际 24 小时时不得写完成。物理 WAN 恢复与 DHCP 单接口续租也要分别验收。

## 恢复

先隔离校园上游，再按自己的已验证正常停止和备份流程操作。配置备份、设备专属校准分区与通用固件用途不同；本仓库不包含任何人的备份。没有实测的串口/TFTP/bootloader 路线应如实标未演练，不提供保证成功的恢复承诺。仅文件/服务改造通常应先考虑可验证的配置回滚，而不是直接写 NAND。
