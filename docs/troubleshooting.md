# 上不了网时，按哪一层查

先确认自己的 Wi-Fi 能否连接、管理页能否打开，再向校园侧查。这样能较快分清无线问题、认证问题和拿地址的问题。

| 现象 | 下一步 |
| --- | --- |
| 锐捷或 MiniEAP 打不开 | 记下具体报错，检查版本、CPU 架构、动态依赖和权限 |
| 一直找服务器 | 核对网线、校园侧接口和客户端选择，检查是否有另一份认证客户端 |
| 收到 EAP Failure | 暂停重试，保留这次请求和失败的头部顺序，检查账号、旧会话及拒绝原因 |
| 已 Success，WAN 却没有地址 | 查 WAN 的 DHCP、租约、网关和 DNS |
| 有地址但域名打不开 | 分别测试 DNS、默认路由和目标网站 |
| Wi-Fi 能连，路由器管理页打不开 | 查设备拿到的私人地址，确认连接的是自己的网络 |
| 只有测速失败 | 看状态码、收到的字节和超时时间，再用其他网站对照 |
| 监控显示离线，网页仍正常 | 先检查监控程序和数据时间，再确认路由器上的认证进程 |

电脑同时连接校园 Wi-Fi 时，测试还要看源接口和下一跳，避免把备用连接的结果误当成路由器接入成功。

## 认证交接后失败

现场曾在切换服务后收到 Failure，随后一次正常 Logoff 加冷却使连接恢复。排查因此要留意旧会话：停止 MiniEAP 进程与发送注销帧是两个动作。

更换服务时，先处理旧会话再启动新客户端。如果已记录了明确失败或结果不明的尝试，先读错误和状态，不把“重登到成功”为止当作排障方式。

## 5GHz 暂时找不到

依次看路由器是否仍在广播、电脑扫描是否刷新、是否能关联，以及关联后有没有拿到地址。随后再查实际信道、带宽和无线状态。

原厂代码中存在 CAC 等待分支，但一次 Wi-Fi 不可见还不足以确定是 DFS。保留当时的信道和状态，才能判断该调整哪一项。

## 普通重启后没有认证

检查故障文件属于哪次启动、当前服务有没有真正启动，以及认证进程是否存在。早期实现遇到过关机时留下旧故障、拦住下一次开机的问题，后来调整了关机钩子。

如果需要恢复改造，优先使用自己的配置备份和服务回滚流程。恢复出厂、TFTP 和写固件涉及另外的恢复条件，不是这类服务问题的第一步。

## 监控程序报错

本项目排障时遇到过几种“监控错了，网络仍通”的情况，修改状态读取器时可以对照：

### Lua 读取 JSON 后少了字段

LuCI 解码器可能把 JSON `null` 转为 Lua `nil`，让字段从表中消失。例如 `observer_exit_code: null`，经过重新序列化后可能不见了。[解码器说明](https://github.com/openwrt/luci/blob/master/docs/api/modules/luci.json.html)介绍了相关行为。

读取状态时保留原始 JSON，在接收端检查字段和类型；不要只按 Lua 表的键数判断服务是否运行。然后结合活体进程、DHCP 和网站访问交叉查看。

### 正常回执被当成错误

某版检查器曾把返回码为零、带成功回执的输出误判为失败。应按对应版本的回执格式解析，并记录具体出错阶段和返回码。

同样，命令传输失败也需要分层排查。本次长、短命令对照都曾成功，后来定位到检查器误拒回执，未证实是设备命令长度限制。

## 连续观察中断

先看最后记录时间、观察进程和电脑是否睡眠或离开网络。观察程序退出后，路由器可能仍然联网；这时缺的是后续记录，需要补做观察。

本次 24 小时计划因电脑观察进程退出而中断，保留了约 6 小时 35 分钟的数据。详细结果见[现场记录](field-results.md)。
