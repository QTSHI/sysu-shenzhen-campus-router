# 架构与验证边界

```mermaid
flowchart LR
  Wall[本人校园墙口] --> WAN[核实后的物理 WAN / VLAN]
  WAN --> EAP[一个认证客户端]
  EAP --> DHCP[校园 DHCP / DNS]
  DHCP --> NAT[路由与 NAT]
  NAT --> LAN[私人 LAN 与有密码的 AP]
  WAN -.被动头部.-> Observer[有限 metadata JSONL]
```

认证与 DHCP 是两个阶段。EAP Success 后仍可能只有链路本地地址；必须再核对有效地址、网关、DNS、实际源路由和 HTTPS。电脑备用 Wi-Fi 可保留，验收访问必须绑定私人 LAN 的实际源地址，确认下一跳属于路由器。

生命周期按“只读安全门 → 一次正常注销 → 冷却 → 再验门 → 被动观察器就绪 → 一次认证”设计。成功客户端保持运行；观察器分段轮换不应重启客户端。失败和未知凭据尝试应持久锁存；不能用无限 respawn 掩盖服务端拒绝。后续服务端合法 Identity/MD5 请求与主动重拨不是同一个动作。

普通关机需要先阻止新的客户端、精确结束自己的进程，再在上游接口尚可用时正常注销。关机顺序不能只依靠 cron 行排列；启动时也必须等待 RAM 管理密钥和接口就绪。源码案例曾出现旧启动关机时写入故障锁，阻止下一启动的问题，因此跨启动故障需要核对所属启动及是否使用过凭据，不能一律清除。

本仓库提供观察器、补丁和说明，没有导出现场的管理私钥、安全门摘要或运行凭据，也没有把受设备专属绑定的一次性控制器通用化。要实现自己的服务监督器，至少验证进程 PID/启动时钟/父进程/真实可执行文件、重试预算、故障持久化和关机顺序。

## LAN、广播和性能

- 固定 WAN 与 LAN 桥隔离，私人 DHCP 只服务私人 LAN；广播不应泄漏到校园侧。
- 无线主 AP 的隔离、`maxsta`、WMM、组播转换和桥 snooping 都要先读取实际值，再按两个下游终端互通测试判断。驱动支持某个键不证明本机当前使用该值。
- 设备上限、空口竞争和校园策略不能用“无限”替代实测。关联数也不能证明同时活跃上网。
- 性能比较需要相近时间、同目标、相同传输方式，分别测直连、路由有线下游和无线；同时观察 CPU、内存、丢包及延迟。
- 协议头观察器仅观察 EAPOL。它不能代替 LAN 广播/组播、DHCP 租约或持续互联网可用性测试。
