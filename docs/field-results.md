# 匿名现场结果与使用建议

记录时间：2026-10-21，中国标准时间。对象是本次已核实的 RD03v2 原厂 2.0.28；以下经验不能代替其他硬件版本的核对。

## 已实际通过

- 官方客户端直连及路由器独立接入均见 EAP-MD5 和 EAP Success。路由器取得 DHCP 地址、网关、DNS，电脑以私人 Wi-Fi 地址绑定访问学校与外网 HTTPS 成功，排除了校园 Wi-Fi 和本机代理代为联网。
- 原厂固件保留；未刷写 NAND、修改启动环境或制作启动 U 盘。一次普通重启后，路由器自动认证并重新联网已验收。
- 滚动恢复 v2 服务已在本机安装，普通重启后首次认证、唯一客户端归属和两站 HTTPS 通过。恢复策略为同次开机内每1800秒最多预留两次链路恢复，距上次实际认证启动至少300秒；真正的认证拒绝仍锁存。物理断线恢复尚未实测，不能由普通重启成功代替。
- 主 2.4GHz 与 5GHz AP 均在同一 LAN 桥；校园 WAN 不在该桥。访客网络已关闭。未设置 MAC 白名单或四设备限额。
- 实际 IPv4 前两条转发规则已核对：首条只丢弃独立物联网桥入向，下一条放行桥接流量，位于 LAN 区拒绝规则之前；IPv6 也有桥接放行。无需为主 LAN 放宽 WAN 防火墙。桥过滤表未能独立读取，跨设备收发仍待实测。
- DHCP 地址池容量 250 个；固件配置的每频段最大终端数为 64。这是配置值，不能视为实际满载能力或无限设备承诺。
- QoS 已关闭，未配置上下行限速或分组限额。现有 NSS/ECM 加速组件已加载；不能据此断言每条流都已卸载。

## 吞吐短测

2026-10-21 04:07–04:08，路径为电脑私人 5GHz Wi-Fi → 路由器 → 校园有线网络；默认 TLS 校验、禁用代理、绑定私人源地址并核对实际路由。测试前后认证与 DHCP 均正常，学校和外网两站 HTTPS 均成功。

速率用实际总字节除以整个传输阶段耗时计算，包含连接建立开销；这是小流量短测，未与直连电脑在同一时段做严格对照，不能表示持续速度、套餐上限或千兆能力。上传内容为内存生成的零字节，不读取个人文件；下载正文不落盘。

第一次四路16MB下载得到测速服务 HTTP 403，因此该项不计速度；改用[Cloudflare 官方测速文档](https://github.com/cloudflare/speedtest)中的10MB数据量后，四路下载均返回200并收足字节。旧失败记录保留，未将403当成认证失败。

## 日常使用

近距离和大吞吐优先连接私人5GHz；远距离可使用2.4GHz。无线连接速率不是外网速度。本轮测速前的诊断中，5GHz实际主信道为36、带宽160MHz，电脑短测信号99%、接收PHY约2.4Gbps；这些读数不能单独排除DFS影响。没有实测干扰问题时，不盲目加大发射功率、修改国家码或关闭WMM。

保留校园墙线接固定WAN的接法；认证由路由器完成。需要修改账号密码时仅在本机安全输入，勿提交认证配置、备份、日志正文或密钥到Git。
