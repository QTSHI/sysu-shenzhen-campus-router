# 深圳校区匿名现场结果

记录日期：2026-10-21，时间均为中国标准时间。对象是一处本人宿舍墙口和一台已核实的 **RD03v2 原厂 2.0.28**，运行标准 MiniEAP，**没有刷 OpenWrt**。以下只描述已发生的测试；本轮文档整理没有新增现场网站访问测试或设备操作。路线见[深圳校区指南](shenzhen-campus.md)，性能建议见[网络体验](network-experience.md)。

## 已取得的接入与配置证据

- 官方 Windows 客户端直连，以及路由器校园侧接入，均有 MD5 与 EAP Success 证据。路由器取得有效 DHCP 地址、网关和 DNS；电脑通过私人 Wi-Fi 的来源绑定、路由与正常 TLS 访问校内/公网两站，排除了备用校园无线或本机代理代发。
- 原厂固件保留，没有刷写固件或原始分区、改启动环境或制作启动 U 盘；服务程序和配置保存在原厂数据目录。正常关机顺序修正后，普通重启自动认证及联网已实际验收；这不等于断电冷启动、物理 WAN 拔插或主动续租已通过。
- 校园侧保持一个 MiniEAP 会话。滚动恢复 v2 在同一次开机内每 1800 秒最多预留两次链路恢复工作流，距上次实际认证启动至少 300 秒；真正认证拒绝或未知尝试仍锁存。它的普通启动已测，物理恢复路径仍待验。
- 主 2.4GHz/5GHz AP 在同一私人 LAN 桥，校园 WAN 不在该桥，访客网络关闭；没有配置 MAC 白名单或四设备限额。实际转发规则的接口条件与桥接放行顺序已核对，但配置和防火墙检查不能替代下游两端广播/组播收发。
- DHCP 池容量配置为 250 个，每频段最大终端数配置为 64；不是满载测试，也不是无限设备承诺。
- QoS 关闭，没有配置上下行限速或分组限额；NSS/ECM 组件已加载。组件存在不等于每条流都已卸载。

上述会话、启动和路径结果，不推广为其他宿舍墙口或同名硬件的兼容保证。历史官方指引只提供接入背景；当前 MD5 的判断来自本次头部证据，不能由旧 PEAP 配置推断。

## 两个时段的吞吐短样本

路径为电脑私人 5GHz Wi-Fi → 路由器 → 校园有线网络。测试使用来源绑定和正常 TLS，下载正文不落盘；上传使用生成数据，不读取个人文件。

| 项目 | 凌晨 04:07–04:08 | 上午样本 |
| --- | ---: | ---: |
| 单连接下载 | 123.077Mbps（25MB） | 74.212Mbps（10MB） |
| 四连接下载，合计 40MB | 217.835Mbps | 54.329Mbps |
| 四连接上传，合计 8MB 生成数据 | 52.545Mbps | 12.082Mbps |

凌晨还记录了公网 5 次 ping 平均 17.6ms、到路由器平均 1.6ms，两组均零丢包；重叠 20 秒 CPU 样本约 8.84%。这些少量样本不能说明持续峰值、全天丢包率或全部流量路径的 CPU 瓶颈。

上午的5次公网ICMP样本记录到4次回复，回复平均17.5ms；这组小样本也不足以定位持续丢包或判断原因。

速率按实际字节除以整个传输阶段耗时计算，包含连接建立开销。不同时间的小流量测试没有与电脑直连做严格同时段对照。两次结果不同，**不能据此证明账号限速、固定套餐上限、原厂更快或刷 OpenWrt 后会更快**；千兆链路和无线 PHY 速率也不等于外网吞吐。

### 没有计为完整测速的尝试

大对象 100MB 请求返回 HTTP 403；四路各 25MB 的尝试以及 Hetzner 的部分响应/超时也没有构成完整传输，不计入上表。HTTP 206 本身表示部分响应，不能单独当作完整下载成功。每条连接都需同时核对预期状态码、实际收齐字节和完成状态。

早期四连接、每路16MB的请求同样遇到403；后来采用[Cloudflare 官方测速项目](https://github.com/cloudflare/speedtest)说明的数据请求方式，才得到已收齐的短测样本。失败记录保留；没有把测试目标的403或超时当成校园认证失败。外层程序正常结束，只说明流程结束，不代表它包含的每条下载或上传都成功。
