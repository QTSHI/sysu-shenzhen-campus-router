# 深圳校区宿舍实测记录

日期：2026-10-21，以下均为中国标准时间。设备是 **AX3000T RD03v2，原厂 2.0.28**，校园认证由标准 MiniEAP 完成。接入过程见[深圳校区指南](shenzhen-campus.md)。

## 接入结果

Windows 官方锐捷客户端直连成功后，路由器也完成了认证。记录中出现 Identity、MD5 请求和 EAP Success，随后取得 DHCP 地址、网关和 DNS。电脑改连私人 Wi-Fi 后，访问学校网站和公网网站成功；测试核对了源接口和路由，流量实际经过这台路由器。

原厂系统保留，服务文件和配置放在数据目录中。修正关机顺序后，测试了一次普通重启：路由器能重新认证、获取地址，电脑恢复上网。

## 局域网和服务配置

| 项目 | 当时的配置 |
| --- | --- |
| 校园认证 | 一个 MiniEAP 客户端，未启用 `rjv3` |
| 私人网络 | 2.4GHz、5GHz 主 AP 在同一 LAN 桥，校园 WAN 单独隔离，访客网络关闭 |
| 设备数设置 | DHCP 池 250 个地址，每频段 `maxsta` 配置为 64；未设置四设备限额或 MAC 白名单 |
| QoS | 关闭，未配置上下行限速或分组限额 |
| 加速组件 | NSS/ECM 已加载；未逐条确认流量是否进入硬件卸载 |
| 服务恢复 | 同一次开机内任意连续 30 分钟内最多预留两次恢复流程，距上次认证启动至少 5 分钟 |

这些是配置读数。多设备高负载、实际容量和设备发现互通另列在文末待测项中。

## 两个时段的测速

路径：电脑 → 私人 5GHz Wi-Fi → 路由器 → 校园有线网络。下载数据未保存到磁盘，上传使用生成数据。

| 项目 | 凌晨 04:07–04:08 | 上午 10:42–10:46 |
| --- | ---: | ---: |
| 单连接下载 | 123.077Mbps，25MB | 74.212Mbps，10MB |
| 四连接下载，合计 40MB | 217.835Mbps | 54.329Mbps |
| 四连接上传，合计 8MB | 52.545Mbps | 12.082Mbps |
| 公网 ping | 5/5 回复，平均 17.6ms | 4/5 回复，回复平均 17.5ms |

凌晨到路由器的 5 次 ping 平均 1.6ms，全部回复；测速时重叠的 20 秒 CPU 样本平均占用约 8.84%。

速率按传输的实际字节和整个阶段耗时计算，包含建连开销。这里只做了短测，两个时段也没有同时测电脑直连作为对照。因此目前能说的是“速度波动很大”，还不能把原因定为账号限速、校园拥塞或原厂固件性能。

### 排除掉的测速请求

100MB 下载返回 403，四路各 25MB 的请求及 Hetzner 的部分响应/超时没有传完，均未计入上表。更早的四路各 16MB 请求也遇到了 403。后来按 [Cloudflare 测速项目](https://github.com/cloudflare/speedtest)的数据请求方式得到完整短测样本。

这些失败属于测速请求记录，未据此重启认证客户端。

## 连续观察为什么停在 6 个多小时

计划从 **05:02** 观察到第二天，最后一条记录在 **11:37**。这段时间内：

- 两站成对 HTTPS 探测：**396/396 成功**。
- 路由器认证服务在线采样：**80/80 在线**。
- 记录覆盖：约 **6 小时 35 分钟**。

之后电脑上的观察进程异常退出，原因尚未定位。观察器停止不表示路由器在同一时间断网，但后面的时段没有记录，所以这次 24 小时测试中断。观察程序没有重启，周期跟进也已暂停。
